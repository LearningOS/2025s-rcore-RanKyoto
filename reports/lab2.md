## 二、简答作业
- ### 问题 1
> 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

页表项由物理地址和标志位组成。

- 仅当 V(Valid) 位为 1 时，页表项才是合法的；
- R/W/X 分别控制索引到这个页表项的对应虚拟页面是否允许读/写/取指；
- U(User) 控制索引到这个页表项的对应虚拟页面是否在 CPU 处于 U 特权级的情况下是否被允许访问；
- G(Global) 用于标记全局页面，减少 TLB 刷新开销；
- A(Accessed) 记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过；
- D(Dirty) 则记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过。
- P(Present) 用于标记页面或页表是否存在于物理内存中。
- 保留位(RSW)支持操作系统扩展功能

- ### 问题 2

> 请问哪些异常可能是缺页导致的？

在 RISC-V 中，缺页（Page Fault）会触发以下类型的异常：

- Load Page Fault：加载操作访问未映射的虚拟地址或权限不足的页面。
- Store Page Fault：存储或原子操作访问未映射的虚拟地址或只读页面。
- Instruction Page Fault：执行未映射或不可执行的代码页面。

常见触发场景：
- Lazy Allocation：首次访问未分配物理页的虚拟地址（如mmap的延迟分配）。
- Swap Out：页面被换出到磁盘，页表项标记为无效（P=0）。
- 权限错误：用户态访问内核页（U/S位=0）、写只读页（R/W位=0）

> 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。

- stval（RISC-V）：保存触发缺页的虚拟地址。
- scause（RISC-V）：记录异常类型。
- sepc（RISC-V）：触发异常的指令地址，用于异常处理后恢复执行

> Lazy 策略有哪些好处？

- 减少初始开销：避免一次性加载所有页面（如程序启动时仅加载必要代码段），缩短启动时间。
- 节省内存：仅分配实际使用的页面（如mmap申请10G但实际使用1M时，避免浪费9.99G的页表操作）。
- 按需分配：延迟物理页分配，降低内存碎片化风险。

> 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

SV39采用三级页表，每级页表占4KB（512个页表项，每项8字节）。

- 10G连续内存需映射的页数：10GB/4KB = 2621440
- 三级页表：每个上级页表覆盖1GB空间，需1个一级页表项（覆盖512GB）、1个二级页表项（覆盖1GB）、2,621,440个三级页表项
- 总内存：三级页表占 $(2621440+2)\times 8\text{B}\approx 20 \text{MB}$。

> 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

- 分配时记录元数据：仅保存虚拟地址范围、权限和来源（如磁盘位置或匿名页），不分配物理页或建立页表项。
- 缺页处理流程：
1. 检查触发地址是否属于Lazy区域。
2. 分配物理页，按需加载数据（如从磁盘读取文件内容或填充零页）。
3. 更新页表项，标记为有效（P=1）并设置权限位

> 缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。此时页面失效如何表现在页表项(PTE)上？

当页面被换出到磁盘时：
- 页表项标记为无效（P=0）。
- 保留磁盘位置信息：利用页表项的保留位（如 54-63 位）存储磁盘扇区号或Swap分区偏移。
- 触发缺页时：操作系统从磁盘加载页面到内存，更新页表项为有效（P=1）并恢复权限位

- ### 问题 3 双页表与单页表

> 为了防范侧信道攻击，我们的 OS 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 KPTI ) 

> 在单页表情况下，如何更换页表？

在 RISC-V 中，页表的基地址保存在 satp（Supervisor Address Translation and Protection）寄存器中。更换页表的操作就是修改这个寄存器的值。

> 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

在单页表中，用户态和内核态共享一张页表，必须通过页表项的权限位来实现隔离。
- U=1：允许用户态访问
- U=0：仅允许内核态访问（用户态访问会触发 page fault）

> 单页表有何优势？（回答合理即可）

尽管安全性稍弱，但单页表也有其明显的优点：
| 优势            | 说明                         |
| ------------- | -------------------------- |
| **切换页表开销低**   | 不需要频繁修改 `satp` 和刷新 TLB。    |
| **系统调用开销小**   | 用户态切换到内核态不需要换页表，只需切换特权级即可。 |
| **TLB 命中率更高** | 共享页表能避免频繁切换带来的 TLB 缓存失效。   |
| **实现简单**      | 相对更容易设计和实现，适用于资源受限或教学型系统。  |


> 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？


- 用户态切换到内核态时（例如 syscall、trap）→ 切换为内核页表。
- 内核态返回用户态时 → 恢复为用户页表。

如果我实现单页表操作系统，我会：
- 保留单页表，不在 syscalls 中切换页表。
- 使用权限位（U 位）严格控制用户对内核地址的访问权限。
- 可在 trap handler 中做合法性检查，防止越权访问。
